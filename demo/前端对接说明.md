# 电缆端子 OCR 前端对接说明

## 1. 用途与平台

本交接包供前端程序或其 AI 直接调用 OCR 核心函数，适用于 **Windows 10/11 x64**。后端模块负责人工 ROI 内的 OCR、坐标映射、编号规则、重叠框合并以及结果结构化；前端负责图片选择、ROI 绘制、任务调度、结果展示、人工纠错、意见或评论、数据持久化以及业务 ID。

依赖版本记录在根目录 `requirements.txt` 中。接收方不需要下载 YOLO 源码或 PaddleOCR 源码；该 Demo 当前直接使用 PaddleOCR，不依赖 YOLO。

### 必须发送的文件

保持下面的相对目录结构不变：

```text
terminal_ocr_demo/                         # OCR 核心函数与数据模型
outputs/terminal_id_analysis/
  terminal_id_library.csv                 # 合法编号库
requirements.txt                          # Python 依赖
前端对接说明.md                            # 本文档
```

建议同时发送：

```text
app.py                                    # 可运行界面及调用参考
README_demo.md                            # Demo 操作说明
tests/                                    # 回归测试
pytest.ini
samples/电缆端子2.png                     # 测试样图
电缆端子OCR项目交接与实现约束.md          # 项目事实与约束
```

如果前端只调用核心函数，`app.py` 不是硬依赖，但很适合作为对接示例。不要发送 `.conda-local/`、`.paddlex-cache/`、`outputs/demo_runs/`、`__pycache__/`、`.pytest_cache/`、`mmocr-main/`、历史现场图片或其他大体积临时文件。

## 2. 安装环境并验证 Demo

支持平台为 Windows 10/11 x64，建议安装 64 位 Python 3.10，并把项目放到纯英文短路径，例如 `D:\terminal_ocr_demo`。以下两种环境方式任选一种。

### 方式 A：Python venv

```powershell
py -3.10 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```  

如果 PowerShell 禁止激活脚本，可先在当前终端执行：

```powershell
Set-ExecutionPolicy -Scope Process Bypass
```

### 方式 B：Conda

```powershell
conda create -n terminal-ocr-demo python=3.10 -y
conda activate terminal-ocr-demo
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

安装成功后运行测试：

```powershell
python -m pytest -q
```

启动浏览器参考 Demo：

```powershell
python -m streamlit run app.py --server.port 8501
```

然后访问 `http://localhost:8501`。PyCharm 中可把解释器设置为项目的 `.venv\Scripts\python.exe`，或选择刚创建的 Conda 环境。

本包不携带 PaddleOCR 模型缓存。**首次 OCR** 需要联网下载 PaddleOCR 模型，默认缓存到 `%LOCALAPPDATA%\terminal-ocr-demo\paddlex-cache`；后续运行复用该缓存。恢复环境和导入检查本身不下载模型。

## 3. 前端最小调用示例

必须先配置模型缓存，再导入 OCR 引擎：

```python
from PIL import Image

from terminal_ocr_demo.runtime_env import configure_paddlex_cache

configure_paddlex_cache()

from terminal_ocr_demo.config import DemoConfig
from terminal_ocr_demo.models import ROI
from terminal_ocr_demo.ocr_engine import PaddleOCREngine
from terminal_ocr_demo.pipeline import run_pipeline
from terminal_ocr_demo.result_contract import build_result_items

config = DemoConfig()
engine = PaddleOCREngine(config)  # 初始化昂贵：应用生命周期内缓存并复用

image = Image.open("input.png").convert("RGB")
rois = [
    ROI("roi_001", (544, 283, 734, 695)),
    ROI("roi_002", (560, 720, 706, 981)),
]

result = run_pipeline(image, rois, engine, config)
items = build_result_items(result.detections)

if result.roi_errors:
    print(result.roi_errors)
print(items)
```

前端已有图片对象和 ROI 时，不需要从磁盘读取 `input.png`，直接传入 `PIL.Image.Image` 和 `ROI` 列表即可。

## 4. 输入契约

图片参数：

- 类型为 `PIL.Image.Image`，推荐转换为 RGB。
- 坐标原点是输入原图左上角，单位是原图像素。
- 前端显示图若经过缩放，必须先把 ROI 坐标换算回原图像素。

ROI 定义：

```python
ROI(roi_id: str, bbox: tuple[int, int, int, int])
```

`bbox` 固定为 `(x_min, y_min, x_max, y_max)`。ROI 必须具有正宽和正高，建议前端先把坐标限制到原图范围内。`roi_id` 由前端提供，并在每个结果中原样返回。

主函数契约：

```python
run_pipeline(image, rois, engine, config, rules=None) -> PipelineResult
```

## 5. 输出契约

调用：

```python
items = build_result_items(result.detections)
```

每个结果严格包含以下五个字段：

```python
{
    "roi_id": "roi_001",
    "detection_id": "det_0001",
    "text": "K21C",
    "confidence": 0.908177,
    "polygon": [
        [593.5, 965.0],
        [596.0, 932.0],
        [687.0, 939.0],
        [684.5, 972.0],
    ],
}
```

- `roi_id`：所属人工 ROI 框 ID。
- `detection_id`：当前单次结果列表内从 `det_0001` 开始编号的检测框 ID；它不是跨任务持久化的数据库主键。
- `text`：编号规则处理后的输出字符。若 OCR 明确检测到内容但当前无法可靠确定字符，则为空字符串 `""`，检测框仍会保留，供人工纠错。
- `confidence`：被选中 OCR 候选的原始置信度；特殊情况下可能为 `None`。
- `polygon`：映射回输入原图的四点像素坐标，顺序沿用 OCR 检测框。

CSV 的结构为 `ROI框ID,检测框ID,输出字符,置信度,检测框坐标`，与上述结构使用同一批最终检测结果。CSV 坐标字段保存 `polygon`。

## 6. 错误、耗时与并发

- OCR 是 **CPU 同步耗时** 操作，前端应放入**后台任务或工作线程**执行，并显示适当的忙碌状态或进度。
- `PaddleOCREngine` 初始化昂贵，应在应用生命周期内**缓存并复用**，不能每次点击检测按钮都重新创建。
- 当前引擎**不保证线程安全**；不要让多个线程同时调用同一个实例。并发请求应串行化，或在独立工作进程中使用独立实例。
- 单个 ROI 的异常会写入 `PipelineResult.roi_errors`，其他 ROI 继续处理。前端应向用户提示这些局部错误。
- 模型初始化失败、依赖缺失或合法编号库缺失等全局问题会抛出异常，前端应捕获并显示可理解的失败信息。
- 合法编号库位于 `outputs/terminal_id_analysis/terminal_id_library.csv`，必须保持其相对于项目根目录的位置，或在配置中显式传入绝对路径。

## 7. 可选：保存完整运行产物

如果前端只需要内存中的结构化结果，可以不写文件。如需保留源图、ROI 图、ROI 裁剪、OCR 标注图、CSV 和审计 JSON，可调用：

```python
from terminal_ocr_demo.artifacts import save_run_artifacts

artifacts = save_run_artifacts(
    image=image,
    rois=rois,
    result=result,
    source_filename="input.png",
    output_root=config.output_root,
)
```

返回的 `RunArtifacts` 提供 `run_dir`、`source_image`、`roi_overlay`、`roi_crops`、`ocr_overlay`、`csv_path` 和 `audit_path`。`save_run_artifacts` 是可选步骤，前端也可按自己的存储方式处理五字段结果。

## 8. 模块与职责

- `terminal_ocr_demo/runtime_env.py`：`configure_paddlex_cache`，设置模型缓存环境变量。
- `terminal_ocr_demo/config.py`：`DemoConfig`，阈值、规则库和输出目录等配置。
- `terminal_ocr_demo/models.py`：`ROI`、检测结果和 `PipelineResult` 数据模型。
- `terminal_ocr_demo/ocr_engine.py`：`PaddleOCREngine` 封装。
- `terminal_ocr_demo/pipeline.py`：`run_pipeline`，多 ROI 主流程。
- `terminal_ocr_demo/result_contract.py`：`build_result_items`，生成前端需要的五字段结构。
- `terminal_ocr_demo/artifacts.py`：CSV、ROI 图片、OCR 图片和审计文件。
- `terminal_ocr_demo/rules.py`：编号正则、合法编号库和受限纠错。
- `terminal_ocr_demo/postprocess.py`：空间去重、包含框和碎片框抑制。

## 9. 前端及其 AI 的最小对接清单

1. 保留 `terminal_ocr_demo` 和 `outputs/terminal_id_analysis/terminal_id_library.csv` 的相对位置。
2. 应用启动时先调用 `configure_paddlex_cache()`，再创建并缓存一个 `PaddleOCREngine`。
3. 将界面矩形换算为原图像素后构造 `ROI`，ROI框ID 由前端决定。
4. 在后台调用 `run_pipeline`，不要阻塞界面主线程。
5. 用 `build_result_items` 取得五字段结果，不要自行重新生成检测框 ID。
6. `text == ""` 时标记为待人工补录，不要丢弃检测框。
7. 检查并展示 `roi_errors`；人工纠错、意见栏、业务 ID 和持久化均由前端负责。
8. 需要留档时调用 `save_run_artifacts`。
9. 对接完成后在已激活环境中运行 `python -m pytest -q` 做回归验证。
