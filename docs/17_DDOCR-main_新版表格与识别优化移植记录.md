# DDOCR-main 新版表格与识别优化移植记录

更新日期：2026-10-22。目标代码为 `DDOCR-main`，基于界面端同学新增的 Tabulator 类 Excel 表格。本次保留原有表格编辑、粘贴、填充、撤销、人工确认与端子点保存交互，并接入此前在 `DDOCR_1011` 实现的识别优化。后端原有 REST 接口未变。

## 识别与展示流程

1. 点击开始识别或重新识别后，PPOCR 按当前整图/原选区工作，YOLOX 对整张原图检测端子对。YOLOX 推理服务与 DDOCR 后端部署在同一台服务器，通过回环地址通信。
2. YOLOX 原始点保存在 `terminal_model_points`；保守的二次重叠去重后，有效点保存在 `terminal_points`。端子点人工增删移动仅改变有效点。原始点数与有效点数分开显示，便于核查。
3. OCR 在同一区域内尝试按文字带方向合并横向碎片框，并按甲方确认的编号库与合法字符集合 `0123456789ABCDHJKPUWX-/` 校验。无法可靠修正的非法字符保留原始标记供审计，正式文本留空并提示复核。
4. 默认 ONNX 识别后端可在同一次 CTC 推理中取得完整文本候选。仅当原文恰有一个非法字符、候选完整编号合法且候选/原文模型序列概率达到设定门槛时，才采用候选并标记人工复核。Paddle 后端没有这条候选能力。模型兼容性及现场效果仍须按 [CTC 核查说明](16_OCR_CTC模型候选与部署核查.md) 验证。
5. HE 与 CLAHE 只作为 PPOCR 的可选对照试验，默认关闭；YOLOX 始终使用原图。开关及试验脚本见 [优化方案](15_DDOCR_1011_端子与线号识别优化方案.md)。

## 类 Excel 表格的端子匹配约束

表格数据从 `terminalTableRows()` 进入 Tabulator。每个有效端子点有且仅有一条带端子号的行，编号按图像从上到下为 `1～N`；同高度按从左到右。每条有效 OCR 线号只寻找逻辑纵坐标最近的端子点。若多条线号争同一点，仅距离最近的一条占用，其他线号单独成行、端子号留空且标记“待核对端子”，不会改配第二近的点。即使 OCR 数量不超过端子数量，也可能出现竞争导致的空端子行和无端子号行。

新表格读取保存过的行数据时，未匹配行强制显示空端子号；历史任务中旧式按序号匹配留下的端子号不会在无端子点的行上形成额外编号。该行的端子号单元格只读，补点并保存后重新计算匹配。线号框或端子点移动、增删后，表格重算；未匹配行仍可查看、编辑线号及备注。网页表格和前端 Excel“端子对照表”共用该匹配函数，后端任务导出使用同规则的 Python 实现。
