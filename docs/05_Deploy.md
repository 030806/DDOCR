# 部署与运维

## 1. 开发与测试

Docker Compose 启动：`api`、`worker-cpu`、`postgres`、`redis`、`minio`。测试可使用模拟推理适配器或轻量模型，数据库/Redis/MinIO 集成测试使用真实容器。Alembic 迁移由独立一次性命令执行，不由多个 API 副本并发执行。

## 2. 首期生产部署

- Nginx/Traefik：TLS、反向代理、上传限制和 SSE 长连接配置。
- API：至少两个无状态副本。
- CPU Worker：文件校验、PDF 渲染、缩略图、导出和清理。
- GPU Worker：OCR 推理，按 GPU 和显存设置并发。
- PostgreSQL：主库、自动备份和连接池。
- Redis：访问控制和持久化，用于 Celery 与短期事件。
- MinIO：私有桶、加密、纠删码或可靠磁盘阵列。
- 前端静态资源独立发布，`/api` 代理到 FastAPI。

## 3. 规模化部署

迁移 Kubernetes 后：API 按 CPU/请求量扩容；Worker 按队列深度扩容；GPU Worker 使用 GPU resource limit 和节点选择；模型推理服务按版本独立部署和灰度。PostgreSQL 使用托管高可用或 Patroni，Redis 使用 Sentinel/Cluster，对象存储使用 S3 或分布式 MinIO。

## 4. 发布流程

静态检查和测试 → 构建不可变版本镜像 → 数据库迁移兼容检查 → 测试环境契约/E2E → 灰度 API/Worker → 观察错误率和队列 → 全量。

数据库变更采用 expand/migrate/contract，滚动发布期间新旧版本兼容。OpenAPI schema 在 CI 中保存并做 breaking-change 检查，防止已有接口被修改。

## 5. 安全与资源限制

- 内网敏感部署支持离线运行、传输加密、静态加密和审计。
- 设置文件大小、PDF 页数、单页像素、渲染时间、并发任务和租户配额硬限制。
- 模型制品保存哈希/签名，推理实例只加载已发布版本。
- 原文件、页面图和导出物分别设置生命周期；用户主动删除走逻辑删除和后台清理。

## 6. 可观测性

统一贯穿 `request_id/job_id/page_id`。监控：API P95/P99 和错误率、上传吞吐、校验失败率、对象存储错误、队列深度、排队时间、任务成功率、各阶段耗时、模型每页耗时、模型加载、GPU 利用率/显存/OOM、CPU/内存、数据库连接及低置信度比例。

告警至少覆盖：队列持续增长、失败率突增、GPU OOM、对象存储不可用、数据库连接耗尽和推理实例无健康副本。

## 7. 备份、灾备与容量

- PostgreSQL 每日全量备份和持续 WAL 归档，定期恢复演练。
- 对象存储启用版本控制、跨节点冗余或云端跨区复制。
- 首期建议目标 RPO 15 分钟、RTO 4 小时，生产前由业务确认。
- 容量按日文件数、平均页数、标准图大小、每页结果数和保留期估算。
- GPU 按峰值页/秒和模型 P95 每页耗时估算。
- 降级：推理不可用时任务保留排队；SSE 不可用时轮询；导出拥塞独立限流，不影响 OCR 主链路。
