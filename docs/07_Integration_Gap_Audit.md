# 前后端联调缺口审计

审计日期：2026-07-21。

## Milestone 1（已完成）

- **Correction**：前端已连接纠正创建接口，提交 `base_revision`，并处理 409
  revision 冲突；保存后使用服务端 revision 和纠正文本更新页面。
- **Comment**：留言新增、修改、删除均已连接后端；只有留言作者可以修改或删除。
- **Current User**：纠正创建人和留言作者来自 Bearer 会话中的当前登录用户，
  不再使用固定 Mock 作者；相关复核接口要求登录。

## P0（已完成）

- 文件、文件内容、任务、页面、结果、纠正、留言和导出接口均要求 Bearer Token。
- 上传文件和 OCR 任务写入 `owner_id`；所有下游访问通过任务/文件归属校验。
- 任务列表只返回当前用户任务；跨用户资源访问统一返回 404，避免泄露资源存在性。
- Konva 原图改为 axios 携带 Authorization 下载 Blob，再使用临时 Object URL
  展示；原图接口不再匿名开放。

## 尚未连接

### P1：任务闭环

1. **任务删除**：任务页只从前端数组移除；后端尚未实现
   `DELETE /ocr/jobs/{job_id}`。
2. **导出**：工作台使用浏览器 `xlsx` 导出当前内存数据；任务页甚至仍从
   `mock.ts` 取结果。后端导出创建、状态查询和下载接口尚未接入前端。
3. **任务状态刷新**：后端当前同步生成固定结果；前端没有轮询或 SSE，因此未来
   接真实异步 OCR 后无法持续更新进度。
4. **服务端筛选/分页**：前端一次获取最多 100 条后在浏览器筛选、排序；尚未使用
   jobs API 的 query/status/sort/cursor 参数完成服务端分页。

### P1：OCR 与文档能力

1. **真实 OCR 引擎**：创建任务仍固定生成 `XT-101/QF10I/24V DC`，未调用真实
   OCR 模型。
2. **模型目录**：模型选择来自 `mock.ts`；创建任务固定提交 `mock@1.0.0`，没有
   连接 `GET /models` 返回的模型与版本。
3. **PDF 页面展示**：PDF 可上传，但没有渲染为逐页图片，Konva 只能展示上传的
   PNG/JPG/JPEG。

### P2：残余 Mock 展示 

1. 无 `taskId` 的默认工作台仍加载 `mock.ts` 页面。
2. 结果面板页脚仍显示“Mock 数据”。
3. 顶部文件名仍通过 `mock/tasks.ts` 查找，FastAPI 新任务会回退显示
   `QC_Report_0714.pdf`。
4. `MockPage`、`mockPageNumbers` 等类型命名仍泄漏 Mock 实现，可在业务功能稳定后
   统一重命名，不影响当前接口。

3. 异步任务进度、服务端分页及 PDF 渲染。
