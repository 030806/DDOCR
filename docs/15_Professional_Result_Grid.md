# OCR 专业数据表格

识别工作区的“表格显示”使用 Tabulator 6.3，保留“列表显示”及现有 REST API。表格是 OCR 业务数据的编辑视图，不提供公式、自由插入行、合并单元格或工作簿导入。

## 操作

- 双击端子号、线缆编号或备注进入编辑。人工确认列点击切换。
- 人工确认列也可纵向拖选：从未确认行开始会将范围内可编辑行全部确认，从已确认行开始会全部取消；向上、向下拖动均支持，范围外状态保留。只读空白行跳过，端子点编辑期间不可批量确认。一次拖选通过原接口自动保存，并作为一个操作支持撤销和重做，不改变“选择”列的勾选状态。
- Tab / Shift+Tab 向右 / 向左移动；Enter / Shift+Enter 向下 / 向上移动。编辑中的中文输入法确认不触发跳转。Esc 取消本次输入。
- 鼠标拖动选择矩形单元格区域，Ctrl+C 复制；选中起点后 Ctrl+V 粘贴 Excel 的多行多列文本。编辑器内保留原生文本复制粘贴。
- 粘贴按当前可见行顺序进行。超出边界或包含非法值时整次拒绝；只读列跳过并提示数量。制表符、换行和 Excel 引号转义均支持。
- “向下填充”或 Ctrl+D 用选区第一行的值填充选区后续行。
- 行首复选框支持不连续多选；Shift+点击另一个行首复选框连续选择，也可以在“选择”列纵向拖选多行。从未勾选行开始拖动会勾选范围内所有行，从已勾选行开始拖动会取消范围内所有行；再次拖选同一区域可取消，范围外的选择保留，向上或向下拖动均适用。上方“全选当前”选择当前显示行。复选框同步显示实际选中状态；在业务单元格内拖选仍用于复制和填充。
- “顺序编号”支持直接框选端子号列的单元格后操作，无需勾选行。端子号单元格选区（含单个单元格）优先于勾选行；其他列的选区不参与编号，继续以勾选行为目标。弹窗明确显示来源、行数及表格行号，并锁定本次目标范围。
- 编号支持起始值、正整数步长、数字位数、前缀和后缀。预览表逐行显示修改前、修改后及处理方式，包含已有编号和只读行的跳过原因；默认跳过已有人工值且不消耗编号，勾选覆盖后替换已有值。修改参数时实时更新预览，确认前不写入，取消不会修改数据。只读端子空白行保持跳过，整次应用支持一次撤销。
- 端子点模式的编号弹窗显示模型原始识别数量（缺失时显示未知）、当前端子点数量以及“仅修改编号文字，不新增端子”的说明。编号数值不以端子数量为上限，例如两个端子允许编号为 `101、102`。
- 原有“一键填充端子号”保留：按当前显示行号填写所选空白端子号，与可配置连续编号不同。
- 工具栏撤销 / 重做，或表格非编辑状态下 Ctrl+Z / Ctrl+Y / Ctrl+Shift+Z。一次粘贴、填充或编号作为一个操作撤销。已保存内容的撤销也会提交服务器。
- 拖动表头边界调整列宽；表头随表格纵向滚动保持固定。“放大表格”提供更大的操作空间，退出后保留草稿和选区。列宽为当前会话状态。
- 点击结果行继续定位原图检测框；从原图选择结果会定位并高亮对应行。

## 业务限制

端子号与线号始终作为文本处理，`001`、`1-2`、`=ABC` 不作数字、日期或公式转换。与原接口一致，保存时去掉字段首尾空白。线号不能为空；端子号和线号最多 500 字符，备注最多 1000 字符。粘贴人工确认接受 `是/否`、`已确认/未确认`、`true/false` 和 `1/0`，空值为否。

端子点模式中，以实际端子点数量作为边界，不能以 `max(端子点数量, OCR 结果数)` 得到的表格行数作为端子数量。行适配层提供 `hasTerminal`、`hasOcrResult`、`requiresTerminalReview` 三种标识：

- 有端子且有 OCR 线号：端子号允许编辑、粘贴、填充和顺序编号，通过原接口持久化；导出使用修改后的编号。未填写人工端子号时回退显示自动序号。
- 有端子但无 OCR 线号：保留自动端子号，业务字段只读，补充线号仍使用现有新增检测框功能。
- 有 OCR 线号但未匹配到端子点：内部标记“待核对端子”，表格端子号单元格直接留空；该格禁止编辑、粘贴和填充，点击时提示核对原图，编号预览中跳过该行。确有漏检时先补充并保存端子点；线号和备注仍可纠正。既有历史编号保留在数据中，但该行在表格与端子对照导出中显示空端子号，不会形成额外编号。

当前端子与线号按逻辑上下位置最近点一对一匹配；同一点竞争时由距离最近者占用，其余线号保持空端子号行。自动匹配仍需人工核对物理接线关系。筛选隐藏的结果不参与操作。普通 OCR 模式没有端子点数据，保留原有端子号编辑规则。

进入端子点编辑前必须处理表格待保存项；端子点编辑期间暂停表格修改和编号，防止未保存补点提前放开编号权限。保存端子点时，若存在新增或删除，先显示新增数、删除数、修改前后端子总数和对应关系核对提示，用户可“确认保存”或“返回检查”。取消不发保存请求、不丢弃草稿；单纯移动点不触发数量确认。新增与删除数量相抵时也须确认。保存成功后按新数量重新计算表格边界。

## 保存、冲突与离开保护

所有修改以稳定结果 ID 和字段名关联，行号只用于显示。排序不改变检测框和结果的关联。

保存模块维护独立草稿、操作历史和队列；同一结果串行、不同结果最多四行并发。单行的端子号、确认状态、备注尽可能合并，通过现有表格接口保存；线号通过原纠正接口保存。正在保存时的新输入不会被旧请求回调覆盖。

表格不展示“保存状态”列，工具栏保留保存中、失败或冲突的数量提示。批量操作可以部分成功，现有接口不提供跨行事务。失败保留草稿，通过“重试失败项”重试。版本冲突停止该行自动保存，在表格外展示服务器最新字段；核对后使用“已核对，重试我的修改”明确重试。网络失败重试按钮不会自动重试冲突行。

切页沿用未保存保护；任务离开和现有端子排侧边切换流程复用 `hasPendingEdits / flushPendingEdits`。有待保存、失败或冲突时不能完成复核。历史仅覆盖当前页面编辑，刷新页面后不保留未保存草稿或撤销历史。

## 实现与验证

- `src/components/OcrResultGrid.vue`：Tabulator 适配、矩形选区、剪贴板、键盘、多行选择及编号设置。
- `src/ocrGridEditing.ts`：文本解析、校验、连续编号、草稿、保存队列、撤销重做。
- `src/components/OCRResultPanel.vue`：行适配和现有工作区集成。
- `src/ocrGridEditing.test.ts`：剪贴板、文本编号、按 ID 保存、批量校验、保存后和保存中撤销、新旧输入竞争、失败重试、冲突暂停及并发限制。

运行 `npm test` 和 `npm run build` 检查回归及类型。`npm run test:grid` 使用已安装的 Chrome 运行 `tests/grid` 中的浏览器验收，自动启动本地 Vite 服务；也可用 `PLAYWRIGHT_CHANNEL` 选择其他已安装的浏览器通道。截图输出在 `.codex-output/grid-playwright`。浏览器用例使用真实表格和保存队列、模拟保存回调，覆盖编辑导航、拖选复制粘贴、填充、Shift 连选、编号、持久化撤销重做、失败重试、排序、联动、冲突确认、越界粘贴和端子点只读行；不替代真实后端多用户集成验收。中文输入法需补充人工验收。

本次下载的 `DDOCR-main` 未包含 `tests/grid` 浏览器用例，本轮未运行 `npm run test:grid`；需在部署环境补做类 Excel 表格的浏览器与中文输入法验收。
