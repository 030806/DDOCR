# DDOCR-main 功能核对清单（界面端联调版）

适用版本：2026-10-22 整合版 `DDOCR-main`，即界面端类 Excel 表格版本加上本轮识别优化。供界面端同学逐项验证；每项填写「通过 / 未通过 / 未测」及任务编号、图片名、截图。**代码已通过自动化测试，但以下真实图片效果和浏览器操作仍须现场核对。** 本清单不是识别准确率合格承诺。

## 一、开始前固定测试条件

- [ ] 记录前端构建版本/提交号、后端版本/提交号、浏览器、测试日期；确认网页右侧可切换「列表显示 / 表格显示」，表格有「选择、序号、端子号、线缆编号、人工确认、备注」列，以及「向下填充、顺序编号」等按钮。如果还是旧表格，先排查服务器上的前端构建文件、部署目录和浏览器缓存，暂不要据此判断模型功能有问题。
- [ ] 记录图片名称、原图尺寸、任务 ID、是否选区、OCR 后端（ONNX/Paddle）、实际识别模型、`DDOCR_OCR_ILLUMINATION` 值。用**同一张原图**对比不同选区或预处理模式，避免因图片不同产生误判。
- [ ] 让部署同学确认 YOLOX 服务在服务器本机的 `/health` 正常、权重已加载，DDOCR 后端已设置 `DDOCR_YOLOX_URL`；DDOCR 与 YOLOX 在同一服务器上由回环地址通信，浏览器无需直接访问 YOLOX。权重应位于打包后的 `backend/model_weights/terminal_pair_yolox_s/best_ckpt.pth`，源码位于 `third_party/YOLOX`。
- [ ] 准备至少 5 类实图：①正常光照且端子/线号清晰；②端子底部密集、曾出现重叠蓝点；③一个线号被拆成多个文字框；④端子漏检或线号漏检；⑤反光、阴影或倾斜。为每图人工记录真实端子对数、完整线号及实际对应关系。`X16B6` 仅是碎片拼接示例，不是甲方确认的合法编号。
- [ ] 建议每轮先拍「原图 + 蓝点 + 列表 + 表格」截图，再做人工编辑；否则人工补点、纠错会掩盖模型原始效果。记录三个数量：`N_raw`=YOLOX 原始点数，`N_auto`=去重后的自动有效点数，`N`=人工增删后当前有效点数。列表/表格中的有效 OCR 线号数记为 `M`。

## 二、识别流程与端子点

### A01 整图识别的双模型结果

- [ ] 不画选区，点击「开始识别」，等待任务完成。**预期：**PPOCR 识别整图线号；YOLOX 识别整张原图端子对。图片上显示蓝色**中心点**，不显示 YOLOX 检测矩形框；右侧既有 OCR 列表，也能切换表格。逐个蓝点对照原图中的物理端子对，记录漏点、重复点、错点。

### A02 选区识别仍检测整图端子

- [ ] 在同一图上仅圈住一部分线号后开始识别。**预期：**OCR 只处理选区，YOLOX 仍看整张原图；选区外的真实端子点仍应显示。对比 A01，OCR 项目可减少，端子点不应仅因为选区缩小而被截断。模型本身的小幅波动应记录原始点数和截图再判断。

### A03 重新识别沿用原选区

- [ ] 对 A02 的任务点击「重新识别」。**预期：**新任务的 PPOCR 继续沿用原选区，YOLOX 再次检测整图；不能悄悄改成 OCR 整图，也不能把旧任务的人工点直接当作本次模型原始结果。查看新任务 ID 和选区边界。

### A04 原始点、去重点与显示点

- [ ] 在重叠蓝点样图上核对每个物理端子。**预期：**仅高度确定属于同一物理端子对的多个模型框被合为一个有效蓝点；相邻两个真实端子不能误合并。页面显示「端子对 N 个」；原始点数与有效点数不同时，另显示「模型原始 M 个」。去重前后数量和具体位置均要记录，不能只凭蓝点变少就判定优化成功。

### A05 检出零个与服务失败

- [ ] 用一张确实无端子的图片，或由部署同学提供可控的零检测样例。**预期：**YOLOX 正常返回零点时可显示「端子对 0 个」，端子点数据为 `[]`；这与 YOLOX 服务不可用不同。若服务不可用，页面应显示「端子检测不可用」及原因，端子点为 `null`，已有 OCR 流程和结果仍可用；记录服务日志与任务页面响应，勿把故障当作真实零端子。

### A06 人工补点、删点、移动点

- [ ] 进入「编辑端子点」：在**原图内部**空白处点击补点、选中点删除、拖动点调整位置，分别保存并刷新。**预期：**点落在实际点击位置，缩放后位置仍正确；画布留白处不生成点。补点/删点使 `N` 和表格的端子行数同步 ±1；移动只改变位置及可能的匹配关系。原始模型点数 `N_raw` 不因人工操作而改变。点数变化时出现确认提示；取消编辑应恢复保存前状态。

### A07 点保存与重新加载

- [ ] 补点后保存，离开任务再打开或刷新浏览器。**预期：**人工点位置、数量和表格匹配结果仍在。若两人同时编辑同一任务，后保存者应得到版本冲突提示，不应静默覆盖他人的点。

## 三、OCR 优化

### B01 横向碎片框合并

- [ ] 找到同一线号被 OCR 拆为左右两个框的实图，例如左框 `X16B`、右框 `6`。**预期：**当右框中心落在左框上下边延长的文字带内，且间距、高度、方向等条件也符合时，两框拼为**一个**检测结果；列表只出现一项，框覆盖整条文字，原碎片信息可追溯。拼成 `X16B6` 后仍可能标为待核对，因为该完整编号不在已确认规则内。只看“有没有合并”，不能把它误当成“编号已经合法”。

### B02 防止跨行或跨线号误合并

- [ ] 用上下相邻、水平接近的两条完整线号测试。**预期：**不同物理线号仍是两项；已完整且各自有效的编号不被错误拼接。若发生误合并，记录两原框坐标、文本、原图及合并后结果。

### B03 合法字符与完整编号分开判断

- [ ] 查看含 `-`、`/` 的 OCR 文本，以及中文、全角括号 `（` 等异常文本。**预期：**字符字典允许 `0123456789ABCDHJKPUWX-/`；半角 `-`、`/` 不会仅因字符筛选被删除，但**字符合法不等于完整编号获甲方确认**。含未定义完整格式的编号仍须人工核对。若有字典外字符且没有可靠模型候选，正式识别文本留空，框与原始误识信息保留，并提示待核对；不能直接将中文/括号作为正式线号，也不能凭格式猜一个字母。

### B04 ONNX 模型概率候选替换

- [ ] 仅在实际使用兼容 CTC 的 ONNX 识别模型、字符表匹配且有可复现错字样图时测试。**预期：**若原文**恰有一个非法字符**、模型同次前向给出的完整文本候选只在该字符处不同、候选符合完整编号规则，且候选/原文序列概率达到门槛（默认 `0.5`），才采用该候选；结果仍标记人工复核。结果属性中应能看到原文、候选及 `assessment.match_method=model_probability_correction`。界面上的整条 OCR 置信度仍对应原始首选文本，**不是**替换后字符的概率。
- [ ] 对候选概率不足、多个非法字符或候选不合法的样例复查。**预期：**不强制替换，正式文本按非法字符规则处理。若实际使用 Paddle 后端，当前没有这条 CTC 候选功能；若 ONNX 未配置自定义模型路径，默认可能使用 RapidOCR 自带识别权重，不能仅凭配置名认定已经用上微调 PPOCR 权重。部署同学可在服务器 `backend` 目录运行 `python scripts/check_ocr_candidates.py --image /absolute/path/to/test_photo.jpg`，核对实际模型路径、字符表和 `ctc_candidate_capture_active`。

### B05 HE 与 CLAHE 光照对照

- [ ] 用同一批正常、强反光、阴影图分别在 `DDOCR_OCR_ILLUMINATION=none`（默认）、`he`、`clahe` 下运行，配置变更后重启相应后端进程。**预期：**只改变 PPOCR 的亮度预处理；YOLOX 仍看原图。记录每图完整线号正确数、误识/非法字符数、碎片数和耗时。HE/CLAHE **尚未被证明一定提升**，某张图没有改善不是代码必然失效；若 YOLOX 输入或蓝点因开关被换成预处理图，则属于实现问题。

## 四、端子与线号位置匹配：重点核对

**总约束：**先按有效蓝点从图像上到下编号；同一高度从左到右。无人工改号时，应有且仅有 `N` 条“关联真实端子点的编号行”，编号为 `1～N`；一个点最多配一个线号。若有 `U` 条有效 OCR 线号因竞争未匹配，表格总行数为 **`N+U`**，额外行的端子号必须为空。用户可以修改已匹配行的编号文字，但不能靠多出一条 OCR 结果凭空生成新端子点。下面示意坐标是测试思路，不要求图片恰好为这些像素值。

### C01 中间漏线号不造成后续错位

- [ ] 找到三个上下排列的点，分别靠近高度约 100、200、300；只在第一、第三点附近有 OCR 线号。**预期：**表格为 `1—线号A / 2—空白 / 3—线号C`，第三条不会因第二条缺失而被塞到端子 2。线号与点应按**逻辑纵向位置最近**匹配，而不是端子列表与 OCR 列表各自排序后逐项对齐。

### C02 多条线号争同一端子

- [ ] 找到两个线号都最靠近同一个蓝点的样例。**预期：**逻辑纵向距离较小的一条占用该点；另一条保留为**端子号空白**的「待核对端子」行，不能改配第二近的点。即使 `M≤N` 也可能发生此情况。记录两框位置和两个点位置，核对赢家是否合理。

### C03 OCR 数多于端子点

- [ ] 在 `M>N` 样例中逐一核对 OCR 项。**预期：**所有有效线号在表格中可见；未匹配的线号另占一行，端子号为空并显示「待核对端子」。带端子点的行仍只有 `N` 条；表格总行数可以超过 `N`，但不能出现不存在的第 `N+1` 个端子号。未匹配行可以插在中间，不保证全在表尾。

### C04 端子点数多于 OCR 线号

- [ ] 在 `N>M` 样例中核对所有蓝点。**预期：**每个点仍占一行，没配上 OCR 的线缆编号为空；带端子点的行数等于 `N`，不能因 OCR 少检就删掉端子行。可通过人工纠错或后续重识处理，但不能把其他线号顺延错配。

### C05 倾斜图、框移动与点移动

- [ ] 用明显倾斜的实图，检查线号四点框与端子点的对应关系；再在「编辑框」或「编辑端子点」中移动一个对象并保存。**预期：**框的倾角可靠时按文字方向投影到端子横向位置比较上下关系；倾角不可靠时用框中心。保存位置变化后表格重新匹配、行顺序按图像位置调整；移动点本身不增加端子数。不要以横向像素距离最近作为预期规则。

### C06 排除误检和已删除 OCR

- [ ] 将某条 OCR 结果标为误检或删除，再恢复。**预期：**误检/删除项不参与端子配对；恢复后重新参与。有效端子点的行仍在，且列表的误检/删除状态与表格可见内容一致。

### C07 旧数据中的历史端子号

- [ ] 打开旧任务中可能保存过“按顺序配对”的端子号，重点看如今未匹配的 OCR 行。**预期：**该行端子号显示为空且只读，不会把历史保存编号变成额外端子。其线号和备注仍可查看/修改；确有漏检时应先补点并保存，再看系统重算匹配。点击这类空端子号单元格会提示核对端子。

## 五、新版类 Excel 表格与人工修正

### D01 列表/表格切换和图表联动

- [ ] 切换「列表显示 / 表格显示」，点击图像中的 OCR 框，再点击表格对应行。**预期：**同一 OCR 结果被选中并能定位；蓝点与 OCR 框视觉样式不同。表格中端子空线号行也有可选行；「全选当前」及已选数量按当前显示行工作。

### D02 单元格编辑与自动保存

- [ ] 双击已匹配行的线缆编号、端子号、备注进行编辑，切走单元格。**预期：**出现待保存/保存中/已保存状态，刷新后仍在。线缆编号不能为空；端子号只允许在**关联端子点且有 OCR 结果**的行修改；仅有点但没有 OCR 的行只读；未匹配 OCR 行的端子号只读。表格编辑不会改变蓝点数。线缆编号为人工纠正，不应被当作模型自动识别准确率。

### D03 键盘、复制粘贴和向下填充

- [ ] 用 Tab 左右、Enter 上下导航；框选若干格后 Ctrl+C/V 从 Excel 复制粘贴；再选择至少两行同列做 Ctrl+D 或点「向下填充」。**预期：**按表格行列落值，首行作为向下填充源；只读格跳过并提示数量；粘贴越界或值非法时整次粘贴不应用任何修改。人工确认列的粘贴值限 `是/否`、`true/false`、`1/0` 等受支持形式。

### D04 行选择与人工确认批量操作

- [ ] 点击选择列、Shift 连选及纵向拖选；在人工确认列纵向拖选。**预期：**选择数与实际行一致；确认列从未确认行拖选可批量确认，从已确认行拖选可批量取消；只读行跳过。批量删除/误检/恢复只处理被选行关联的 OCR 结果，空线号的端子行不能作为 OCR 删除请求提交。

### D05 顺序编号

- [ ] 选中端子号单元格区域，或勾选若干行，点击「顺序编号」；设置起始值、步长、数字位数、前后缀，先检查修改前后预览再应用。**预期：**端子号单元格选区优先于勾选行；默认跳过已有编号且不消耗编号，勾选「覆盖已有端子号」才覆盖；待核对端子的空号行和纯端子无 OCR 行跳过；应用仅改已有行的编号文字，**不新增端子点或表格行**。

### D06 撤销、重做、保存失败与冲突

- [ ] 修改一个单元格并使用工具栏撤销/重做（也可 Ctrl+Z、Ctrl+Y）；用测试环境人为制造一次网络保存失败或双人并发修改。**预期：**撤销/重做恢复可见值并按现有保存流程提交；保存失败保留用户输入并给出重试入口；版本冲突显示服务器当前值，由用户核对后主动重试，不能静默覆盖。只有在可控测试环境制造故障。

### D07 编辑端子点时的表格保护

- [ ] 表格改动尚在保存中时进入端子点编辑；再尝试直接改表格或顺序编号。**预期：**先完成或处理待保存项；端子点编辑期间表格操作被禁用并提示先保存/退出。点数增删保存前有确认，保存后表格按新点重新计算；取消则不改变已保存数据。

### D08 放大表格、页面切换与刷新

- [ ] 点击「放大表格」后编辑一项，再退出放大、切换页面/任务并刷新。**预期：**同一页数据及保存状态一致，不出现重复行、旧选区残留或丢失已保存的线号/备注/人工确认。

## 六、导出与结果一致性

### E01 前端 Excel 导出

- [ ] 对 A01、C02、C03、C04 至少各导出一次「精简」「完整」结果。**预期：**Excel 除相应 OCR 结果表外，图片任务还含「端子对照表」。对照表的端子号/线号配对与当前表格一致：端子点对应行数为 `N`，未匹配 OCR 行端子号为空，未配线号的端子行线号为空。注意「精简结果」「完整结果」是 OCR 清单，不能拿它们的行数当端子数。

### E02 后端任务导出

- [ ] 若界面提供服务器任务导出，也导出同一任务。**预期：**其「端子对照表」与网页、前端 Excel 在有效点数、配对关系和空白行上相同；若自定义端子号或人工纠正已保存，刷新后再导出并对照。发现差异时保留三个结果文件和任务 ID。

### E03 无端子结果与历史任务

- [ ] 测试 YOLOX 正常检出零点和无端子检测记录的历史任务。**预期：**零点时有效 OCR 仍可见，但未匹配行的端子号为空；历史无端子记录或服务失败时，不应误报「模型识别 0 个」，也不能让整个 OCR 页面不可用。记录 `terminal_points` 是 `[]` 还是 `null`。

## 七、判定问题时至少留下这些证据

每个未通过项复制下列模板一份：

```text
清单编号：
图片名 / 任务 ID / 页码：
前后端版本、OCR 后端/模型、预处理模式：
操作步骤（含整图或选区）：
人工真值：真实端子数、真实线号、应配对关系
实际数量：N_raw=，N_auto=，N=，M=，未匹配线号 U=
预期结果：
实际结果：
截图：原图带蓝点、OCR 列表、表格、必要时 Excel
补充：浏览器控制台/失败请求、后端日志、YOLOX 日志或结果 JSON（请隐去账号和令牌）
是否在刷新/重新识别后复现：
```

优先按下面的区别定位：

| 现象 | 先检查 | 不应直接得出的结论 |
| --- | --- | --- |
| 看不到新版表格按钮 | 实际前端构建、部署目录、浏览器缓存 | 模型未生效 |
| 看不到蓝点 | YOLOX `/health`、后端 `DDOCR_YOLOX_URL`、页面 `terminal_error` 与 `terminal_points` | 所有图片都没有端子 |
| 蓝点数量不准 | `N_raw` 与 `N_auto`、原图中真实端子、重复点位置 | 只要数量相等就代表匹配正确 |
| 端子号和线号错行 | 蓝点/文字框实际坐标、倾角、竞争同一点情况 | 必然是排序代码没执行 |
| 括号没有被替换 | OCR 实际后端、识别模型与字符表、CTC 捕获、候选门槛、完整编号规则 | 任何非法字都应该自动变成合法字 |
| HE/CLAHE 结果不变或变差 | 环境变量是否生效、测试图是否相同、原图光照 | HE/CLAHE 必然优于原图 |

**通过标准：**先确认所有硬规则（双模型区域、蓝点/端子数量、单点最多一线号、无端子号的多余线号仍可见、保存与导出一致）均成立；真实图片上的漏检、误检、OCR 错字和光照效果另按人工真值逐图统计。发现硬规则不成立是功能缺陷；规则成立但模型没有识准，应记录样图并归为模型效果问题。对于本轮仍未完成的远端 GPU、现场图片和浏览器完整验收，不应只凭单元测试通过就勾选「通过」。
