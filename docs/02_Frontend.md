# 前端架构与后端接入

识别结果面板固定使用列表展示。用户可点击“按坐标排序”，将当前页面中包含人工新增框在内的可见结果按检测框 `y1` 从上到下排列；同一纵坐标时按 `x1` 从左到右排列。排序仅影响当前页面展示，不修改 OCR 结果和检测框坐标。

## 1. 当前结论

现有组件层级、Konva 独立渲染、结果面板和弹窗/抽屉边界可以保留。`WorkspaceView` 继续负责编排，但 HTTP、状态机和缓存应移到 service/composable。

当前需要修正的生产边界：

- 缺少统一 HTTP client、错误模型、鉴权刷新、请求取消和 request_id。
- `OcrItem`、`MockPage`、`ModelOption` 位于 Mock 文件，应迁移到领域类型。
- 全局可变 `pages` 会造成跨任务数据污染。
- Mock 类型适合演示，不得直接作为生产 API 类型。

## 2. 推荐新增结构

```text
src/api/http.ts                 统一请求、鉴权、错误、取消和 request_id
src/api/models.ts               模型目录 API
src/api/files.ts                上传 API
src/api/jobs.ts                 任务与 SSE API
src/api/results.ts              页面与 OCR 结果 API
src/api/review.ts               纠正与留言 API
src/api/users.ts                用户与偏好 API
src/composables/useOcrJob.ts     当前任务状态机和页面加载
src/types/api.ts                通用响应与错误类型
src/types/ocr.ts                页面、结果和坐标类型
```

UI 组件继续通过 props/emits 工作，不在组件内部散落 HTTP 调用。

## 3. 前端状态边界

后端持久化：上传文件、模型版本、任务及进度、标准页图、OCR 原始结果、纠正历史、留言、删除状态、用户权限和后台导出。

前端会话状态：当前结果 ID、当前页、搜索词、低置信度开关、请求加载状态。

本地或可选用户偏好：列表/原位模式、缩放、分割面板宽度、默认模型、低置信度阈值、是否显示置信度和导出类型。

签名 URL、任务事实状态、作者和服务端时间不得保存为客户端事实来源。

## 4. `useOcrJob` 建议接口

```text
job
pages
currentPage
currentPageResults
selectedResultId
isLoading
isSubmittingCorrection
isSubmittingComment
loadJob()
loadPage(pageNo)
createJob()
cancelJob()
retryJob()
```

数据按 `job_id + page_no` 隔离和缓存。路由切换时取消旧页面请求和 SSE。纠正与留言允许乐观更新，但失败必须回滚；409 必须用服务端最新修订覆盖缓存后提示冲突。

## 5. API 到 UI 的兼容映射

| API | 当前 UI | 迁移要求 |
|---|---|---|
| `confidence` | `score` | 适配层可短期映射，长期统一为 confidence |
| `display_text` | `corrected || text` | UI 最终显示 display_text |
| `comment.author.name` | `comment.author` | UI 不得自行生成作者 |
| `comment.created_at` | `comment.time` | 仅展示层格式化 |
| `image.width_px/height_px` | 固定画布尺寸 | 必须用 API 尺寸替换固定值 |

`id`、`text`、`bbox` 和从 1 开始的页码可保留。模型选择必须提交 `model_id` 与明确的 `model_version`，不能提交展示字符串。

## 6. Mock 退出策略

- Mock 仅引用 `src/types` 的正式领域类型。
- 每完成一个真实 API，将对应数据源切换到 `src/api`，不重写现有 UI。
- 真实任务按路由 ID 加载，禁止继续使用全局共享结果数组。
- 接口接入完成后保留 Mock 作为开发演示/测试 fixture，而非生产回退数据源。

## 7. 工作台真实数据初始化

识别结果区支持搜索、最低置信度滑块、0/50/70/90 快捷阈值、低置信度筛选，过滤结果同步作用于列表、原位布局和图片检测框。“低置信度”按钮与滑块共享动态阈值：普通模式显示大于等于阈值的结果，低置信度模式显示低于阈值的结果；选择“全部”时使用系统默认低置信度阈值。用户可单条或批量标记误检、删除和恢复结果，并撤销最近一次操作。误检与删除均采用服务端软状态持久化，默认隐藏，且始终从精简和完整导出中排除。

原位布局使用页面真实 `sourceWidth/sourceHeight` 映射检测框，保持空白背景。框内文字单行省略，悬停或选中后显示完整文字浮层；位于画布右侧的浮层自动向左展开。工具栏提供适应窗口、50%～300% 放大缩小，放大后可通过滚动条检查局部区域。

左侧图片查看器支持 55%～300% 缩放，设置抽屉可选择最高 300% 的默认缩放比例；“适应窗口”保持 82%。

图片工具栏提供检测框编辑模式。普通状态下，包含 `polygon` 的结果使用闭合四边形显示，旧数据继续使用 bbox 矩形；进入编辑后，旧 bbox 会自动生成左上、右上、右下、左下四个角点。用户可分别拖动四个角点形成旋转矩形、一般四边形或轻微透视框，也可整体拖动检测框；控制点始终限制在文档范围内，交叉或退化四边形不会被接受。

单框调整过程中点击“确认”才会写入页面草稿和撤销历史，点击“取消”恢复该框调整前坐标。确认时保存真实四点 `polygon`，并以四点 min/max 重算兼容 `bbox`。空白区域仍可拖画新框，新框必须由用户填写文字，不触发 OCR，并显示“人工新增”。Delete 软删除选中框，Ctrl+Z/Ctrl+Y 支持最多 50 步撤销重做。页面工具栏“保存”通过批量事务接口提交全部已确认修改；存在待确认或未保存修改时，切页、切任务或关闭页面会受到拦截。

四边形主体与四个角点使用独立的 Konva 拖动节点，拖动统一通过 Stage 指针位置换算为原图坐标，避免缩放状态下父子节点位移叠加。工具栏明确区分“确认本框”“取消调整”和“保存全部”：前两者处理当前框草稿，保存全部只在当前框已确认后启用。
检测框发生变化后工具栏显示“当前框待确认”；确认或取消完成后展示操作消息，避免仅依赖按钮启用状态判断操作是否生效。
进入检测框编辑模式后，撤销、重做、确认、取消和保存操作显示在画布工具栏的独立第二行；主工具栏仅保留编辑开关和缩放，窄窗口下第二行允许横向滚动。
图片工作台中的检测框不再按置信度着色：普通框统一使用浅灰色，当前选中框及其四个控制点使用红色高亮。置信度数值和低置信度筛选逻辑保持不变。

- `/workspace` 始终以空页面集、空结果选中状态启动，不从 `mock.ts` 注入默认页面、OCR 结果或文件信息。
- `/workspace/:taskId` 通过 `GET /ocr/jobs/{job_id}`、`GET /ocr/jobs/{job_id}/pages` 及分页结果接口加载真实任务。
- 页面图像继续通过鉴权 HTTP 请求转换为 Blob URL，离开任务时释放。
- 上传区通过 `GET /models` 读取可用模型，创建任务时提交服务器返回的 `model_id` 和 `model_version`。
- 任务加载失败时回到空工作台，不使用 Mock 数据降级。
- `mock.ts` 保留供后续统一清理，不再是工作台运行时数据源。

## 8. 独立区域 OCR 任务

上传区在普通“开始识别”之外提供“局部框选识别”。首期仅对 PNG/JPG 启用；用户在 `RegionJobModal` 中按原图比例拖画最多 20 个矩形，前端将显示坐标换算为原图像素 bbox，宽高不足 16 px 的草稿不会加入区域列表。确认后先上传文件，再调用新增区域任务接口并跳转 `/workspace/{new_job_id}`。

已完成或部分成功任务在任务历史和图片工具栏提供“区域识别”。历史入口以 `action=region` 打开来源任务，来源页面加载完成后弹出同一选择器；提交时只传 `source_job_id`，不上传或复制文件。检测框编辑模式与区域创建互斥。

区域创建弹窗必须明确提示“创建独立任务，不修改来源任务”。任务创建后继续使用标准轮询、页面结果、审核、纠正、留言和导出 UI。首期不支持 PDF 框选、选区移动缩放及跨页区域；这些能力依赖服务端 PDF 分页标准图。

区域任务的结果顺序由服务端基于原图坐标统一生成，与用户框选区域的先后无关；列表按 `y1` 从上到下排列，同一高度按 `x1` 从左到右排列。
