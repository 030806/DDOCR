# 系统安全检查记录

日期：2026-10-28。范围：当前工作区的认证、上传及业务数据一致性相关源码；使用独立临时数据库验证认证行为，未操作实际业务数据，未修改业务实现。本次不是完整渗透测试，不能据此认定不存在其他问题。

## 已通过隔离测试确认

### P1：登录验证码可被绕过，答案可直接读取

位置：`backend/app/api/routes.py` 登录接口、`backend/app/services/core.py` 的 `create_captcha()` 与 `login_user()`；前端 `src/views/AuthView.vue`。

前端先调用验证码验证，再调用登录；后端登录只接受手机号和密码，不校验验证码验证凭证。直接登录不需要验证验证码。验证码图片是 SVG，答案以 `<text>` 文本包含在返回内容中，解码即可读取。

影响：验证码无法阻止自动化登录尝试。尚未发现应用层登录限速，部署层限制需单独核实。

建议：将一次性验证码验证结果与登录请求或受保护的登录流程绑定；使用不能直接提取文字答案的图片生成方式，并增加登录失败限速。修复需遵守不修改已有接口契约的项目约束，先确定兼容实现方案。

### P1：修改密码后旧会话仍可访问

位置：`backend/app/services/core.py` 的 `change_password()`。

隔离验证：注册获取旧令牌，修改密码，再以旧令牌调用会话认证，仍成功。重置密码流程会撤销会话，但普通修改密码流程没有对应处理。

影响：已经泄露的令牌不会因用户修改密码而失效。

建议：修改密码与旧会话撤销保持事务一致，明确当前会话的重新登录或换发规则。测试多个登录会话及密码更新失败的场景。

### P2：新会话没有过期时间

位置：`backend/app/repositories/auth.py` 的 `SessionRepository.create()`、`user_id_for_active_token()`，以及 `backend/app/models/schema.py` 的 `sessions`。

创建会话不填写 `expires_at`；认证允许该字段为空。隔离数据库确认新令牌的该字段为 NULL。

影响：令牌没有自动失效时间，除非主动退出或撤销。与修改密码未撤销会话组合，会延长令牌泄露后的影响。

建议：设置明确的会话寿命，兼容处理历史 NULL 会话，补充到期前后、主动撤销和多会话测试。

## 静态确认的风险，未做压力验证

### P2：上传大小检查晚于请求体完整读入

位置：`backend/app/api/routes.py:159` 起的 `upload_content()`；`backend/app/services/core.py:285` 起的 `save_content()`。

接口先 `await request.body()`，再查找文件和检查内容是否超过 200 MiB。应用会先接收并在内存中聚合请求体，才拒绝超大内容；认证用户请求不存在的文件也会先进入读体步骤。

建议：先验证目标文件权限，流式累计读取并在超限时立即中止；部署层设置请求体和并发限制。不能仅信任 Content-Length。测试无此头、伪报大小、分块上传、超限及并发场景。

实际服务可用性影响取决于网关配置和资源限制，本次未发送大请求。

### P2：验证码缓存未主动清理过期项

位置：`backend/app/services/core.py` 的 `_captchas`、`create_captcha()`、`verify_captcha()`。

创建验证码写入进程字典，只有验证时弹出；未验证的过期验证码没有清理和容量上限。验证码接口无需认证。多进程部署时，创建与验证落到不同进程也可能验证失败。

建议：使用带 TTL 和容量限制的共享缓存，限制生成频率，并验证过期回收和多进程一致性。
