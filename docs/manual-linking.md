# 端子与线号人工匹配

向导第 4 步依次选择起始和末尾端子。两个端子之间的孔位参与编号，编号方向由起始端子指向末尾端子；起始端子位于图片下方时，编号向上生成。区间外孔位仍保留在骨架中。旧版只保存起始端子的流程继续按“起点至图片底部”处理。

识别完成后，端子行始终按图片从上到下排列。线号识别结果也按图片从上到下排列，并依次作为这些端子的初始关联；超出端子数量的线号单独排在表尾。初始关联会随端子业务记录保存，可以直接编辑、保存、导出和进入合并流程。表格不再显示“关系”列，列表仍只展示真实 OCR 结果。

向导识别完成时可能给 OCR 结果写入 `terminal_point_id`：它表示该文本框落入某个已确认的线号位置，是流程提供的定位线索。初始业务关联由上下顺序建立，之后以用户保存的关联为准。空文字的端子占位记录不作为线号展示。

在原图工具栏选择“连线匹配”，依次点击端子点和线号检测框即可预览连线。一个端子点与一个线号框最多各参与一条连线。重新连接已有线号会解除旧关联；若目标端子原有线号，该线号转入表尾的未关联结果。原端子行保持在原位并留空，序号和端子号不移动。“撤销上一条”和“解除选中关联”可调整本次预览。“保存并退出”按整页提交；“取消”丢弃未保存修改。图片连线是可选的纠正方式。

表格中剪切并移动线号来源会转移关联。普通复制、向下填充和直接修改文字只修改业务值。初始关联只建立一次；刷新结果或新增 OCR 框不会重新打乱已有端子行和关联。已手工保存的关联优先保留。

新增 `POST /ocr/jobs/{job_id}/pages/{page_no}/terminal-links`，请求包含 `base_revision` 和 `links`（端子点 ID 到 OCR 结果 ID 的映射）。服务端以修订号保护整页保存，要求端子点和 OCR 结果属于当前页且来源唯一。旧的 `terminal-document` 接口保持不变。

识别结果允许大小写字母，输出保留模型或人工输入的大小写。整图 OCR 片段合并的横向距离限制比局部 ROI 更严格，防止跨越端子排合并左右文字。
