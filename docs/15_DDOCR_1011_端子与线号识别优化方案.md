# DDOCR_1011 端子与线号识别优化方案

> 本文保留当时的方案记录。后续关于合法字符、非法字符输出和默认全局 HE 的现行规则，以 [API 说明](04_API.md)及[部署说明](14_YOLOX_端子对接入部署说明.md)为准。

> 状态：方案已确认，代码已按方案修改；真实图片与远端模型效果仍待验收。制定日期：2026 年 10 月 19 日。代码基线为 `C:\Users\99581\Desktop\DDOCR_1011`。本方案针对现场图片的识别与结果展示，不改变原有 PDF 处理范围。

## 1. 目标与不变约束

本轮优化包括：线号碎片框合并、线号与端子点按图像位置匹配、重复端子检测合并、合法字符约束，以及 HE 光照预处理对照测试。YOLOX 仍对整图检测端子对，PPOCR 仍按用户选区或整图识别线号；“重新识别”沿用原选区。两路模型在同一远端部署环境内按现有流程运行，本轮不要求重训模型或更改现有对外接口。

**端子数量是硬约束。** 区分以下三个数量：

- `N_raw`：YOLOX 经过现有推理和 NMS 后返回的原始检测数，保留用于排查重叠检测。
- `N_auto`：将确认为同一物理端子对的重复检测合并后，YOLOX 给出的有效端子点数。未人工编辑时，自动生成的端子号必须且只能是 `1～N_auto`。
- `N`：当前有效端子点数。按既有方案，用户可人工补点、删点或移动点；人工修订后端子号必须且只能是 `1～N`。人工补点是人工修正，不能记作 YOLOX 自动检出。

每个有效端子点在表格中恰有一个带端子号的行，**最多匹配一个线号**；每个有效线号也最多匹配一个端子点。未匹配的线号可以另占表格行，但该行的端子号必须为空，绝不能因为 OCR 结果较多而生成第 `N+1` 个端子号。正常未人工修订时，页面的有效蓝点数、端子号个数和 `N_auto` 一致。YOLOX 检测失败与成功检出 0 个仍须区分。

## 2. 线号碎片框合并

现有 OCR 后处理主要合并重叠、包含的重复检测，对水平分离的 `X16B` 与 `6` 这类碎片不能可靠拼接。新增步骤放在同一 ROI 内的重复候选归并之后、最终编号校验之前，使用原图坐标下的四点框：

1. 按文字阅读方向找到左框与右框。将左框的上、下边向右延长，判断右框中心是否位于两条线形成的文字带内；允许与框高成比例的小幅误差，以兼容倾斜拍摄。
2. 同时检查水平间距相对于文字高度、两框高度和方向的一致性，以及中间是否存在另一条独立线号。只满足“中心位于延长线之间”不能直接合并，避免跨线号误拼。
3. 候选按从左到右顺序拼接，再运行合法字符与完整编号校验；生成覆盖整条文字的四点框，并记录原碎片文字、位置、置信度及合并原因，供人工复核。
4. 几何证据足够时，允许合并后仍属于“待核对”的编号，不能为使其通过规则而任意改字。`X16B6` **只是碎片合并示例，不是新增合法线号**。

验收时既检查漏合并，也检查相邻线号被误合并的情况；原本完整的线号不得因该步骤被拆散或改写。

## 3. 重复端子检测合并

现有 YOLOX 推理已做一次 NMS，但位置略有偏移的框仍可能留下多个蓝点。对 YOLOX 原始框增加二次去重：同时参考框重叠、中心距离、框尺寸及附近端子间距，仅在足以判定为**同一个物理端子对**时组成一组，保留置信度最高的框及其中心点。合并前的框和分数仍保留在原始模型结果中。

去重只在本次模型自动结果进入有效点列表前运行，不对用户人工添加或移动的点再次自动去重。图示底部密集蓝点需要结合原图、原始检测框和真实端子数确认；不能仅按固定像素距离合并，因为紧邻的两个真实端子也可能很近。阈值从代表性现场图片与已有标注数据中确定，并检查“重复点减少”与“真实点未被误删”两项结果。

## 4. 端子点与线号的坐标匹配

现状是端子点和 OCR 框各自从上到下排序后按序号并排，任一侧漏检会造成后续行整体错配。本轮改为逐线号寻找图像中**逻辑上下位置最近**的端子点，而不是按两个列表的序号配对。

1. 将有效端子点按原图中的从上到下位置编号 `1～N`。线号位置取四点框中心；四点框倾角可靠时，可将其文字方向投影到端子所在横向位置，以比较同一水平行，倾角不可靠时退回中心纵坐标。横向像素距离不直接决定配对。
2. 每条有效线号独立计算其最近端子点，**不设“距离太远就一定不匹配”的硬阈值**：只要该最近点最终未被别的线号占用，就与它配对。
3. 如果多条线号指向同一个最近点，由逻辑纵向距离最小的一条占用该点；同距时按稳定的坐标与结果 ID 规则打破平局。其余线号单独成行、端子号留空，**不改配第二近的端子**。这使结果不依赖线号进入算法的先后顺序。
4. 未匹配到线号的端子仍显示其端子号，线号列留空。误检或已删除的 OCR 项不参与匹配；人工新增、删除、移动线号框或端子点后立即重算。最终仍由用户核对现场接线关系。

表格总行数因此为 **`N + 未匹配线号数`**，可能大于旧方案的 `max(N, M)`；但有端子号的行始终严格为 `N` 行。未匹配线号按图像上下位置插入相应位置，端子号列留空，保证全部有效线号在表格中可见。例如有效端子点在纵坐标 100、200，线号在 105、110、205：105 和 205 分别配对端子 1、2；110 单独一行，端子号为空。网页表格、前端 Excel 导出和后端 Excel 导出必须得到同一配对结果。

## 5. 合法字符与编号校验

以 `output/terminal_id_analysis` 中甲方确认的分析结果为依据：当前编号库有 104 种线号、385 条出现记录；库中已出现的字符集合为 `0123456789ABCDHJKPUWX`。按本次补充要求，**合法字符字典额外加入半角 `-` 和 `/`**，因此允许的单字符集合为 `0123456789ABCDHJKPUWX-/`。完整编号仍按已确认的编号库及既有基础/扩展格式规则判断；“字符合法”不等于“整个编号合法”。现有编号库尚无带 `-` 或 `/` 的编号，也未规定这两个字符在完整编号中的位置或组合方式，因此包含它们的识别文本可以保留并标记待核对，不能仅因字符合法就自动判定为已确认编号。例如字符 `B` 和 `6` 分别合法，不代表 `B6` 是已确认后缀。本轮不因碎片示例扩展 `B6` 规则。

当前 PPOCR 接口只返回每个框的首选文本和整体置信度，没有逐字符的次优候选；因此不能仅在后处理加一个字典，就声称能把首选 `（` 自动换成模型的次优合法字符。实施分两层：

1. 对可获得的识别候选进行合法字符约束，并在完整编号库/格式规则中校验；只有能取得模型逐字符候选或识别 logits 时，才选择概率最高的合法替代字符。记录替代前后文本、候选分数，并对自动替代标记复核。半角 `-`、`/` 不应在字符筛选阶段被删除。
2. 如果识别文本的字符都在字典内，但整体不符合现有编号库或格式（包括尚无完整规则的 `-`、`/` 编号），保留该文本并标记待人工核对。若文本含中文、全角括号等字典外字符，且接口没有可靠候选可替换，则保留检测框及原始文本用于审计，正式识别结果留空并标记待核对，不把非法字符直接输出，也不凭规则臆造字符。

编号库在分析目录与运行时资源目录中的 104 个编号条目一致；实现阶段应将甲方确认目录作为核对来源，避免形成两套不同的合法编号定义。

## 6. HE 光照预处理试验

这里的 HE 指直方图均衡化。先以开关控制的离线对照试验比较三组：原流程、全局 HE、CLAHE。预处理仅作用于 PPOCR 输入图像的亮度通道，且在 ROI 裁剪后、缩放与旋转前执行；不改变几何坐标，也不擅自改变 YOLOX 的原图推理输入。

使用同一批强反光、阴影、正常光照现场照片及人工核对结果，比较整条线号正确率、无效字符/误检数量、碎片框数量和推理耗时。只有光照困难样例取得稳定收益、正常样例无明显退化时，才确定是否默认开启全局 HE 或 CLAHE；否则保持原流程默认值，并保留可选试验开关。

## 7. 实施顺序与验收

1. 固定回归样例：包含碎片线号、密集端子点、某端子缺线号、多个线号争同一点、强光照及正常光照；记录人工确认的端子数、线号文本和对应关系。
2. 先完成 YOLOX 自动点去重，再完成 OCR 碎片合并和字符约束，最后按两路有效结果计算匹配；HE 作为单独的 A/B 试验，避免与后处理改动混淆。
3. 检查自动识别时端子号数等于 `N_auto`、人工编辑后等于 `N`，任意端子最多一条线号，所有有效 OCR 结果都能在表格中找到，网页与两种 Excel 导出一致。
4. 为几何边界、竞争配对、漏检、人工编辑、非法字符及 HE 开关补充测试；更新旧方案中“按序号配对、表格恒为 `max(N,M)` 行”的描述和部署说明。已有接口、历史任务及单模型失败时的展示行为保持兼容。
