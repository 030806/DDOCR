# 端子与线号匹配顺序优化

## 数据流

OCR 检测结果先经碎片合并、识别与规则处理，形成最终线号列表。端子点单独由端子对检测生成。表格显示与后端导出均用最终线号列表和端子点做坐标匹配，不能在匹配后再把 OCR 碎片合并。

## 匹配规则

1. 端子点按图像纵坐标排序，作为端子号 1～N；每个端子最多匹配一个线号。
2. 每条线号先找纵向距离最近的端子。四边形角度只用于小幅修正线号的纵坐标：当斜率无效、外推超过相邻端子典型间距的 35% 或超过检测框高度相关上限时，改用检测框中心。只有两个相邻端子距离接近时，才允许修正改变最近端子的选择。
3. 若独立计算的候选匹配使上下相邻线号的端子顺序交叉，本次整张图统一改按检测框中心重新选择最近端子。这样避免一条上方线号连到下方端子、下一条下方线号又连到上方端子。
4. 多条线号争用同一端子时，纵向距离最近的线号获胜；其余线号保留为端子号留空的待核对行，不强制改配第二近的端子。
5. 未匹配的端子保留空白线号行。端子号为数字的行数始终等于有效端子点数；多余线号作为端子号留空的附加行显示和导出。

前端 `src/terminalPairTable.ts` 和后端 `backend/app/terminal_pair/match.py` 使用一致的规则。修改任一侧的阈值或优先级时，需要同步另一侧及对应测试。

## 核查范围

自动测试覆盖：倾斜框外推造成的上下交叉、过大外推的回退、边界附近可接受的小幅修正，以及多线号竞争时的未匹配行。现场复核仍需关注 OCR 本身漏检、误检、碎片未合并及 YOLOX 端子点漏检造成的空行或附加行；匹配算法不会凭空补出检测目标。
