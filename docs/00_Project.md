# 项目说明与实施计划

## 1. 项目目标

构建工业端子排 OCR 系统，支持：

- 用户上传 PDF 或图片。
- 选择已发布 OCR 模型及明确版本。
- 异步执行 OCR 并展示进度。
- 返回文字、BBox 和置信度。
- PDF 多页浏览、检测框与文字列表双向联动。
- 人工纠正、修订历史、撤销和多人冲突检测。
- 结果级留言的新增、查询、编辑和删除。
- 当前页前端 Excel 导出与全任务后端 Excel 导出。
- 任务历史的搜索、筛选、排序、查看、继续复核、重试、取消和删除。
- 用户资料、权限、退出、密码修改或 OIDC 集成。
- 可选的跨设备工作台偏好同步。

系统边界和稳定规则见 [RULES.md](RULES.md)。

## 3. 当前状态

- 前端原型已完成，当前使用 Mock 数据，不调用真实后端。
- `/workspace` 为工作台，`/workspace/:taskId` 模拟历史任务恢复，`/tasks` 为任务记录页。
- 人工纠正、留言和删除当前只修改内存，刷新后恢复。
- 用户资料、密码修改和退出均为 Mock。
- 工作台设置保存在 `ddocr.settings.v1` localStorage。
- 后端尚待实现，API 契约见 [04_API.md](04_API.md)。

## 4. 实施计划（阶段性）

### P0：真实 OCR 主流程

1. 统一响应、错误、鉴权和 request_id。
2. 模型目录 API。
3. 对象存储上传会话、上传确认、文件校验和详情。
4. 创建异步 OCR 任务、任务详情、SSE 与轮询进度。
5. PDF 标准页图、页面列表和单页完整结果。
6. 人工纠正新增，含修订冲突控制。
7. 留言查询和新增。

### P1：任务中心与协作

1. 任务历史搜索、状态筛选、排序和分页。
2. 任务取消、失败页重试和逻辑删除。
3. 纠正历史、撤销和冲突提示。
4. 留言编辑、逻辑删除。
5. 全任务后台 Excel 导出。

### P2：身份、体验与规模化

1. 当前用户、角色、权限、真实退出及 OIDC/密码能力。
2. 可选的用户偏好跨设备同步。
3. 租户配额、完整审计、数据保留和监控告警。
4. GPU 多实例、按模型路由、任务优先级和批量推理。
5. 更多已训练模型、灰度发布、版面/表格/键值对能力。
6. 大规模结果分区、冷热分层和多地域容灾。

## 5. 联调验收

- 上传 PDF/图片后可创建并恢复异步任务。
- 刷新或重新进入 `/workspace/{job_id}` 后任务、页面和进度正确。
- 页面标准图尺寸与 BBox 坐标完全一致。
- 点击结果和 Konva BBox 使用同一稳定 result ID。
- 切换 PDF 页面只显示当前页结果，不发生跨任务数据串联。
- SSE 断线重连或轮询后状态正确。
- 原始文字不被纠正覆盖；并发纠正收到 409 和最新版本。
- 留言作者和时间由服务端生成，刷新后仍存在。
- 任务历史搜索、筛选、排序由服务端分页执行。
- 逻辑删除后旧 URL 返回明确 404/410 或已删除状态。
- 全任务导出不依赖浏览器已加载数据。
- 未登录或无权限用户不能读取文件、页面图、结果和导出文件。

## 6. 当前风险清单（完成后移除）

- 高：现有画布逻辑尺寸 `700 × 760` 与展示尺寸 `2480 × 3508` 不一致；接入后端时必须统一标准页图尺寸。
- 高：全局 Mock `pages` 会让纠正和留言在任务间共享；真实数据必须按 job/page 隔离。
- 高：现有 `corrected` 字符串没有修订版本，不能处理并发和审计。
- 高：Mock 身份不能用于生产，作者、用户、密码和退出必须接真实身份系统。
- 高：执行失败与需要复核必须分别使用 `status` 和 `review_status`。
- 中：单页超大量结果可能造成响应和 Konva 压力，需要压缩或轻量绘制响应，但不能分页漏框。
- 中：签名图片 URL 过期后需刷新页面详情。
- 中：前端尚无统一 HTTP 错误处理、鉴权刷新、请求取消和追踪层。
