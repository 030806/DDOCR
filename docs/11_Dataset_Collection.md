# 复核与增量 OCR 数据入库

## 操作流程

1. 工作台完成文字纠正、四点框修改、加框、删框或误检标记。
2. 点击识别结果列表 footer 的「复核完成」。框编辑草稿会先保存；正在编辑的文字、未确认的单框操作需先完成。确认范围是任务的全部结果，不受搜索、置信度筛选影响。
3. 在任务记录页点击「入库」。原「区域识别」操作在此处替换为入库，工作台的区域识别入口保留。
4. 保存成功显示「已入库」；失败可重试，状态加载失败可点「刷新状态」。

任务表左侧支持多选及跨页选择，仅「已复核」或「入库失败」的任务可勾选。点击「批量入库」前重新读取复核状态，然后逐项调用已有入库接口，显示已处理数量。单项失败不会中止后续任务；成功项取消勾选，失败项保留（如已失去复核资格则取消选择），表格上方展示任务及失败原因。批量执行期间禁用重复提交、勾选和删除，不增加新的后端接口。

当前不额外判断 ROI 是否覆盖全图，也不引入 ROI 专属复核流程。点击「复核完成」代表用户认可当前任务标注可作为整图最终标签；ROI 外漏标由人工复核负责。此规则是本期业务约定。

| 状态 | 入库按钮 |
| --- | --- |
| 未复核 | 入库，禁用 |
| 已复核 | 入库，可点击 |
| 入库中 | 入库中，禁用（当前页面请求期间） |
| 入库失败 | 重试入库，可点击 |
| 已入库 | 已入库，禁用 |

文字、框、有效结果集合修改后，任务版本递增，复核自动失效。留言、搜索、缩放不影响复核。已入库版本仍保留，直到新版本成功发布。历史页面状态是批量查询的快照，其他窗口修改后可刷新；服务端始终检查版本，旧按钮不能绕过检查。

## 新接口

保持已有接口请求和响应不变；以下接口均要求登录，按任务所有者鉴权，使用现有 envelope。

### POST /api/v1/ocr/jobs/{job_id}/review-completion

```json
{
  "expected_results": [
    {"id": "result-uuid", "revision": 0, "geometry_revision": 0, "review_status": "unreviewed"}
  ]
}
```

必须包含当前任务全部结果（包括误检和已删除项），用于检测前端是否基于旧版本复核。后端读取最终文字和框，排除误检及删除项后保存复核快照。结果集合或修订不匹配返回 409，空白文字、`###`、TAB/换行、非法四点框返回 422。空有效结果允许保存 `annotations: []`。

### POST /api/v1/ocr/jobs/{job_id}/dataset-entries

```json
{"reviewed_version": 3}
```

同步完成数据集发布，成功 HTTP 200；未复核、版本变化、同图其他任务已发布新版本返回 409。文件生成失败返回 503，可以重试。同一任务复核版本重复请求不会重复追加标签。

以上两个创建接口支持可选 `Idempotency-Key`（最长 200 字符）：24 小时内相同键和请求返回原响应，不同请求返回 409。前端入库另有「任务 + 复核版本」的自然幂等保障，网络超时可刷新状态或重试。

### POST /api/v1/ocr/jobs/dataset-statuses

```json
{"job_ids": ["job-uuid"]}
```

每次最多 200 个任务，前端自动分批。返回 `data` 数组，每项包含：

```json
{
  "job_id": "job-uuid",
  "state": "reviewed",
  "result_version": 3,
  "reviewed_version": 3,
  "reviewed_at": "2026-09-07T03:00:00+00:00",
  "saved_version": null,
  "image_id": "INC_20260907_000001",
  "last_error": null
}
```

`state` 为 `unreviewed / reviewed / saved / failed`。复核人和服务端时间持久化；推理原始结果和业务纠正历史继续保留，不写入训练 JSON。

## 文件与数据一致性

目录固定在 `DDOCR_DATA_DIR/incremental_ocr_dataset/`：

```text
images/                 原始分辨率图片（实际格式决定扩展名）
records/                最终确认 JSON
crop_img/               四点透视裁剪 JPG
Label.txt               原图相对路径 + TAB + 单行检测 JSON
rec_gt.txt              裁剪相对路径 + TAB + 正确文字
fileState.txt           原图相对路径 + TAB + 1
image_manifest.csv      来源、SHA-256、尺寸、确认时间
.publication.json       内部发布提交信息，用于故障后重试恢复
```

所有文本 UTF-8，路径使用 `/`。四点整数化并规范为左上、右上、右下、左下；保持倾斜几何，不用轴对齐 bbox 替换已有 polygon。当前 `ignore` 和 `difficult` 均为 false，不生成 `rec_gt_trainable.txt`。

当前支持单帧 PNG/JPEG/BMP/WebP/TIFF；暂不支持 PDF、多帧图片及页面尺寸与原图不一致的任务。方向以上传后实际像素为准，不使用画布截图；保留来源文件名，保存扩展名以图片实际编码为准。

`dataset_images` 按所有者及图片字节 SHA-256 去重。数据库主键序列生成全局唯一 `INC_YYYYMMDD_NNNNNN`（日期 UTC，序列跨日期递增，预留未发布编号不复用）。同一原图跨任务复用图片编号；另一个任务覆盖该图后，旧任务必须重新复核。不同用户的记录不通过哈希相互暴露。

`ocr_jobs.result_version` 随标注变更在同一事务递增；`dataset_reviews` 保存确认版本、操作人、时间、最终快照、最近入库版本。入库期间发生编辑时只发布已复核快照，当前任务保持未复核。

## 发布与恢复

本期面向 Demo 数据规模，每次在 `.dataset-stage` 建立完整数据集副本并重建派生文件。发布时保持正式目录不变，先将旧内容复制到 `.dataset-backup`，写入 `.dataset-transaction.json` 事务日志，再通过临时文件和 `os.replace` 更新文件并清理失效标签/裁剪图。这样避免 Windows 对非空目录重命名返回拒绝访问。文件短暂占用时有限重试；更新失败恢复完整旧副本，进程中断则在下一次保存/重建持锁进入时恢复。`.publication.json` 使「文件已发布、数据库尚未更新」的中断可在重试时完成。文件发布完成后的临时目录清理失败延迟到下一次操作，不把已发布数据误报为失败。

同一数据目录使用进程内锁及操作系统文件锁 `.dataset.lock` 串行发布。Windows 和 Linux 均支持；所有后端进程必须共享该目录及支持文件锁的文件系统。维护脚本/训练读取完整数据集时也必须使用 `DatasetFiles.locked()`，或在暂停入库后复制一份快照使用；多文件替换不提供对任意外部读取者的事务隔离。

入库失败现在区分原图读取、文件发布和状态记录阶段，并提示权限/占用或空间不足。服务端诊断日志仅记录任务 ID、阶段、异常类型、errno/winerror，不记录 OCR 正文或数据库请求内容。

本期发布成本随数据集大小增长，需要空间存放正式目录、完整暂存副本及回滚副本（约三份数据）；后续规模化可改为代际目录和快照导出。数据目录包含不同用户数据，仅供受控后端及维护人员使用，不配置为公开静态资源。

从原图和 JSON 重建派生文件（不会修改业务数据库）：

```powershell
cd backend
python -m app.services.dataset_files "D:\path\to\ddocr-data"
```

## 升级与验证

PostgreSQL 正式环境部署前执行 `python -m alembic upgrade head`，迁移为 `d903_dataset_review`。SQLite 开发环境由 Store 自动补齐 `result_version` 并创建新增表。不修改已有任务的单条复核标记，历史任务初始显示未复核。

测试：`python -m pytest tests/test_dataset.py -q`、`npm test`、`npm run build`。覆盖复核版本冲突、鉴权、空标注、非法文字/几何、重复保存、重新编辑、故障重试和并发请求。
