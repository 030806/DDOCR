# 端子排左右侧任务

## 操作流程

顶部「端子排任务」→填写端子排名称→新建。任务包含左侧、右侧、合并结果三个 Tab。
左右侧均使用原单张识别工作台，同一时刻只显示一侧图片。左右指端子排实际方位，不是照片的旋转方向。
任务列表页会提示“填写名称创建新的端子排任务”。进入具体任务后，任务名称、左右侧/合并 Tab 和返回按钮位于同一行；上传操作条使用紧凑高度，右侧识别结果列表固定保留纵向滚动区域。

1. 在左侧或右侧上传图片、预览保存、开始识别。预览时可框选局部识别区域；未框选则识别整图。单页结果完成后自动关联该侧。
2. 纠正线缆号，在「表格显示」中填写端子编号。离开单元格自动保存，切换 Tab 会等待保存；保存失败不会丢弃输入。
3. 「保存并查看右侧」补充另一侧，也可以稍后回来。关联保存在数据库，刷新页面可以恢复。
4. 「关联已有识别结果」选择历史记录及页码。多页新识别需指定关联页，再点击「采用当前结果」。首版每侧只关联一份记录的一页。
5. 「合并结果」按端子编号对应，支持全部/待处理/已确认筛选、批量确认、备注和来源定位。
6. 「导出全部」或「导出已确认」生成 Excel，固定为：序号、端子编号、左侧线缆号、右侧线缆号、人工确认、备注。

重新识别时旧侧别关联保持不变，新识别完成后采用新结果。关联失败可点击「采用当前结果」重试，不必重新上传。
独立 OCR 历史任务及旧导出入口继续保留。左右侧 Tab 的页码、选中结果及缩放在当前应用会话内保留。

## 对应与复核规则

- 只清理端子编号两端空白；不将 `01` 当成 `1`，不删除前缀。
- 同编号在两侧都唯一时自动对应，与 OCR 行顺序无关。单侧缺失保留空单元格。
- 空编号和同侧重复编号保留全部来源，标为冲突，不自动覆盖或丢弃结果。
- 点击线缆号跳转对应单侧图片及识别框，修改编号后刷新合并结果。
- 「调整对应」可指定左右记录，或明确保留单侧行；端子编号必须先填写。不同编号人工对应时以左侧编号展示，界面明确提示。
- 「解除对应」生成独立单侧行，不会在下一次刷新时自动重新配对。
- 来源标为删除/误检后不参与合并。源 OCR 任务被删除后显示不可用，需重新关联再导出。
- 合并确认独立于单侧确认。确认保存来源版本摘要；线缆、编号、几何或来源复核版本变化使确认失效。
- 更换侧别关联或手动调整对应会重置合并确认；原始识别记录、修订与事件保留。
- 初始合并备注组合两侧备注。编辑合并备注后独立保存，不写回源备注。
- 未解决的编号/对应冲突阻止导出；缺侧可以人工核对后确认并导出。

## 新接口

所有接口位于 `/api/v1/terminal-tasks`，需要现有 Bearer 认证，只允许任务所有者访问。
新增接口使用现有 `data/request_id` 信封和错误格式；已有 OCR API 契约不变。

| 方法及路径 | 请求内容 | 返回 |
| --- | --- | --- |
| POST 空路径 | `name` | 新任务 |
| GET 空路径 | `offset=0&limit=50`，limit 最大 100 | `items,next_offset`，带侧别、行数和复核计数 |
| GET `/{id}` 或 `/{id}/rows` | 无 | 任务、侧别、合并行、`revision,version` |
| PUT `/{id}/sides/{left或right}` | `job_id,page_no,base_revision` | 更新后的任务 |
| PATCH `/{id}/rows` | `base_revision,version,rows:[{id,confirmed,note}]` | 更新后的任务，支持批量 |
| POST `/{id}/links` | `base_revision,version,left,right`，来源 ID 或 null | 更新后的任务 |
| POST `/{id}/exports` | `base_revision,version,scope:all或confirmed` | `id,download_url` |
| GET `/{id}/exports/{export_id}` | 无 | Excel 文件 |

创建及写入接口支持 `Idempotency-Key`。版本过期返回 409，不能静默覆盖。
`revision` 是端子排任务配置/复核版本，`version` 同时包含最新来源数据摘要；确认和导出都校验。
关联接口仅接受已完成/部分完成任务中存在的页。同一任务内，同一个识别页不能同时作为左右侧。
导出将当时的行内容写入不可变快照；之后下载同一导出不会混入后续纠错。Excel 单元格按文字写入，保留前导零并避免公式解释。

## 数据库与部署

新增四张表：`terminal_tasks`、`terminal_sides`、`terminal_reviews`、`terminal_events`。
任务持有用户及租户 ID；侧别引用现有 OCR 任务和页码；复核保存来源摘要、操作人和时间；事件保留关联、配对、复核和导出快照。
不迁移或猜测历史 OCR 任务侧别，由用户主动关联。

正式部署先备份数据库，在后端环境执行：

```powershell
cd backend
python -m alembic upgrade head
```

新迁移版本为 `f280_terminal_tasks`，父版本 `e71e7f702135`。生产 PostgreSQL 必须执行迁移后再启动新版服务。
测试和本地 SQLite 由现有 `create_all` 创建新增表。此次开发测试使用独立数据库，没有对业务数据库执行迁移。
